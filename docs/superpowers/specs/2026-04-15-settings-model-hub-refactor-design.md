# 设计规格：设置页面与模型中心深度重构 (Refactor 2.1)

## 1. 背景与目标
解决设置页面改版后出现的功能缺失和体验问题，包括模型选择不可见、模型列表同步不全、搜索功能失效以及排名逻辑空洞等。

## 2. 核心架构变更

### 2.1 后端增强 (Rust)
- **ModelHubManager ( manager.rs )**:
    - 将 `sync_from_ollama` 的采样限制从 20 提升至 100。
    - 改进正则表达式/解析逻辑，从 Ollama 官网 HTML 中提取真实的 `pulls` (下载量) 和 `updated` (更新时间)。
- **GeoSensor ( geo.rs )**:
    - 实现探测结果的进程内缓存，避免频繁触发 HTTP Probe 导致的页面响应迟缓。
- **Search Command**:
    - 新增 `search_hub_models` 命令，支持关键词实时检索全量在线模型库（模拟官网搜索行为）。

### 2.2 前端重构 (Vue 3)
- **ModelManager.vue**:
    - **顶部面板**: 新增 `InstalledModels` 区域，展示本地已就绪的模型卡片。
    - **核心选单**: 显式渲染 `Chat Model` 和 `Embedding Model` 下拉选择器。
    - **搜索逻辑**: 绑定 ENTER 事件至后端搜索 API，支持动态渲染搜索结果。
    - **UI 状态**: 为下载、搜索、同步过程增加明显的 Loading 骨架屏或指示器。
- **Settings.vue**:
    - 移除所有针对 "Intel Mac" 的特定标签和机型文案。
    - 重构 "推理推优" 提示，基于硬件属性显示通用的性能建议。

## 3. 数据流设计
1. 用户进入页面 -> 触发 `fetchModelHub`。
2. 后端检查缓存（24h） -> 返回 100+ 热门模型。
3. 用户输入关键字并回车 -> 前端调用 `search_hub_models` -> 后端抓取实时结果 -> 返回并展示。
4. 用户点击已安装卡片 -> pinia store 更新配置 -> 后端保存持久化设置。

## 4. 验收标准
- [ ] 设置页面加载时间明显改善（<1s 呈现基础 UI）。
- [ ] 已下载的模型在顶部常驻显示。
- [ ] 能够通过回车搜索到本地未缓存的模型。
- [ ] 模型排行榜显示真实的 Pulls 数量。
- [ ] 能够正常切换对话和嵌入模型，并获得正确反馈。

## 5. 风险与不确定性
- Ollama 官网 HTML 结构变更可能导致解析失败（需要稳健的解析保底逻辑）。
- 实时搜索受网络环境影响（需加强超时处理）。
